`@developmentsprint/nuxt-openfeature` connects a Nuxt 4 application to
[OpenFeature](https://openfeature.dev), the vendor-neutral feature flag
standard.

- **Server-side evaluation.** Flags resolve in Nitro. The browser receives
  evaluated values, never provider SDKs or credentials.
- **Five providers, one API.** Flagsmith, PostHog, Vercel Flags, environment
  variables and in-memory flags. Switching vendors is a config change.
- **Fallback chains.** List several providers. The first one that knows a flag
  answers, so you can layer a vendor over env-var overrides over static
  defaults.
- **Request-isolated targeting.** Context travels with each request and is
  passed straight to that request's evaluations.
- **Fail-safe by design.** Provider errors and slow providers return your
  configured default instead of failing the page.
- **Explicit public surface.** Only flags listed in `publicFlags` reach the
  browser.
- **Typed values.** Booleans, strings, numbers and JSON objects, with the
  default's type choosing the matching OpenFeature resolver.
- **Nuxt layers aware.** Split flag configuration across layers.
- **Lazy vendor SDKs.** Provider packages are optional peers and load only when
  configured.

## Safe context propagation

A Nuxt server handles requests from many users at once. The module reads
targeting context from each request and passes it directly to that request's
flag evaluations, without storing user context on the shared OpenFeature client
or global API. This avoids the shared-state bug where one user's targeting
attributes affect another user's flags.

During server-side rendering, supply context from the current server request;
the browser context plugin runs only on the client. See
[Context and targeting](/guide/context-and-targeting).

## Requirements

- Nuxt 4
- `@openfeature/server-sdk` 1.20 or later
- `@tanstack/vue-query` 5, for the client composables and component
- The SDK of each vendor you use. See [Providers](/guide/providers).
