## Install the package

Install the module with its required peer dependencies:

::code-group
```bash [pnpm]
pnpm add @developmentsprint/nuxt-openfeature @openfeature/server-sdk @tanstack/vue-query
```

```bash [npm]
npm install @developmentsprint/nuxt-openfeature @openfeature/server-sdk @tanstack/vue-query
```

```bash [yarn]
yarn add @developmentsprint/nuxt-openfeature @openfeature/server-sdk @tanstack/vue-query
```
::

Then add the SDK for each vendor you use. See [Providers](/guide/providers).
The in-memory and env providers need none.

## Register the module

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@developmentsprint/nuxt-openfeature']
})
```

## Register TanStack Query

The client composables and the `<FeatureFlag>` component cache flags with
[TanStack Query](https://tanstack.com/query/latest/docs/framework/vue/overview).
The module does not register it for you. Add a plugin once, unless your app
already provides a `QueryClient`:

```ts [app/plugins/vue-query.ts]
import { QueryClient, VueQueryPlugin } from '@tanstack/vue-query'

export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.use(VueQueryPlugin, { queryClient: new QueryClient() })
})
```

::warning
Without it, `useFeatureFlag` throws `No 'queryClient' found in Vue context`.
::

## Identify the signed-in user

To target flags by user, store the signed-in user in `useState('auth-user')`.
See [Signed-in user](/guide/context-and-targeting#signed-in-user) for the
expected shape. Without it, flags are evaluated with browser context only.

## Migrate from the previous scope

Version 0.2.5 continues the package under DevelopmentSprint. Replace the old
dependency:

::code-group
```bash [pnpm]
pnpm remove @ribrewguy/nuxt-openfeature
pnpm add @developmentsprint/nuxt-openfeature
```

```bash [npm]
npm uninstall @ribrewguy/nuxt-openfeature
npm install @developmentsprint/nuxt-openfeature
```

```bash [yarn]
yarn remove @ribrewguy/nuxt-openfeature
yarn add @developmentsprint/nuxt-openfeature
```
::

Then use `@developmentsprint/nuxt-openfeature` in `modules` and in imports,
including any `/types` or `/runtime/` subpaths.

::note
The `openFeature` configuration key and every runtime API are unchanged by the
scope migration.
::
