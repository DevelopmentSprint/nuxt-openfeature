## Composables and component

Auto-imported in the Vue app.

| Name | Description |
| --- | --- |
| `useFeatureFlag(flagKey, options?)` | `{ enabled, value, pending, error, refresh }` for one public flag. See [Composables](/reference/composables#usefeatureflag). |
| `useFeatureFlags(options?)` | `{ data, isPending, error, refetch }` with every public flag. See [Composables](/reference/composables#usefeatureflagsoptions). |
| `<FeatureFlag name default?>` | Default slot when enabled, `#fallback` otherwise, nothing while pending. See [FeatureFlag component](/reference/component). |

A client-only plugin attaches [targeting context](/guide/context-and-targeting)
to every flag request. It needs no setup.

## Server helpers

Auto-imported in Nitro server code.

| Function | Description |
| --- | --- |
| `evaluateFeatureFlag(flagKey, defaultValue, context?, options?)` | Evaluates any flag your providers know about. The default's type selects the resolver, and it is returned on error. `options` is `{ timeoutMs? }`. See [Server evaluation](/guide/server-evaluation). |
| `getFeatureFlagContext(event, serverContext?)` | The request's evaluation context: browser context merged with `{ targetingKey?, traits? }`, where your values win. |

::note
The module's other server utilities are auto-imported as a side effect of
registering its utils directory. They are internal and may change between
releases; use only the helpers above.
::

## Routes

Mounted under `flagRouteBase`, `/api/feature-flags` by default.

| Route | Returns |
| --- | --- |
| `GET {flagRouteBase}` | `{ flags }` for every key in `publicFlags`. |
| `GET {flagRouteBase}/:key` | `{ enabled }` for one flag, evaluated against a boolean default. |
| `GET {flagRouteBase}/diagnostics` | Provider types and per-provider flag snapshots. Credentials are omitted. |

See [Endpoints](/reference/endpoints).
