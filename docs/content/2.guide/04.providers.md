Providers are tried in order and the first match wins. Install only the SDKs
you use.

| `type` | Install | Credentials |
| --- | --- | --- |
| `in-memory` | — | Flags defined in `flags` |
| `env` | — | `OPENFEATURE_FLAG_*` variables (prefix configurable with `envPrefix`) |
| `flagsmith` | `flagsmith-nodejs @openfeature/flagsmith-provider` | `FLAGSMITH_ENVIRONMENT_KEY`, optional `FLAGSMITH_URL` |
| `posthog` | `posthog-node` | `POSTHOG_API_KEY`, optional `POSTHOG_HOST` |
| `vercel` | `@vercel/flags-core` | `FLAGS` connection string |

Credentials can also be passed through each provider's `options`. Vendor
guides: [Flagsmith](/guide/flagsmith), [PostHog](/guide/posthog),
[Vercel Flags](/guide/vercel).

## Fallback chains

A production setup might put a vendor first, with environment overrides and
static defaults behind it:

```ts [nuxt.config.ts]
openFeature: {
  providers: [
    { type: 'flagsmith' }, // reads FLAGSMITH_ENVIRONMENT_KEY
    { type: 'env' },       // OPENFEATURE_FLAG_NEW_CHECKOUT=true → 'new-checkout'
    { type: 'in-memory', flags: { /* ... */ } }
  ],
  publicFlags: { 'new-checkout': false }
}
```

With no providers, every flag resolves to its default. See
[Runtime behavior](/guide/runtime-behavior).

## In-memory

Static flags defined in configuration. Useful for local development, tests and
safe defaults at the end of a chain.

```ts [nuxt.config.ts]
openFeature: {
  providers: [
    {
      type: 'in-memory',
      flags: {
        'ui-variant': {
          variants: { control: 'control', v2: 'v2' },
          defaultVariant: 'control'
        }
      }
    }
  ]
}
```

`defaultVariant` must match a key in `variants`.

## Env

Reads flags from environment variables with a prefix, `OPENFEATURE_FLAG_` by
default:

```bash
MY_APP_FLAG_BETA_CHECKOUT=true
MY_APP_FLAG_UI_VARIANT=v2
```

```ts [nuxt.config.ts]
openFeature: {
  providers: [{ type: 'env', envPrefix: 'MY_APP_FLAG_' }]
}
```

`MY_APP_FLAG_BETA_CHECKOUT` becomes flag key `beta-checkout`.
