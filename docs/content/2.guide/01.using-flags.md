`useFeatureFlag`, `useFeatureFlags` and `<FeatureFlag>` are auto-imported. They
need a registered `QueryClient`; see
[Register TanStack Query](/getting-started/installation#register-tanstack-query).

## One flag

```ts
// `enabled` is a boolean; `value` is the raw evaluated value.
const { enabled, value, pending, error, refresh } = useFeatureFlag('hero-variant', {
  defaultValue: 'control'
})
```

`enabled` uses a boolean value as is, applies JavaScript truthiness to other
values, and falls back to `defaultValue` when the flag is missing.

## Every public flag

```ts
const { data: flags } = useFeatureFlags()
```

## Declarative rendering

`<FeatureFlag>` renders its default slot when the flag is enabled and its
`fallback` slot when it isn't:

```vue
<template>
  <FeatureFlag name="new-checkout">
    <NewCheckout />
    <template #fallback>
      <LegacyCheckout />
    </template>
  </FeatureFlag>
</template>
```

::note
The component renders neither slot while the request is pending, so there is no
flash of the wrong variant.
::

## Fetching and caching

Flags are fetched on the client from `GET {flagRouteBase}` and cached per user,
so they refetch when the user signs in or out. Only keys listed in
[`publicFlags`](/reference/configuration#the-publicflags-allowlist) are
returned.

See the [composables](/reference/composables) and
[component](/reference/component) reference for every option.
